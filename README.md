# Ashgrove: Undead Siege

Multiplayer browser-based zombie survival FPS.

## Overview
- Full WebGL rendering with post-processing (SMAA/FXAA)
- Custom weapon systems and unique per-kill visual effects
- Bot AI, team modes, and multiplayer elements
- Maps and arenas
- Polished HUD, menus, and settings

## Important Notice (Anti-Cheat)
The original source includes a strong notice against adding cheats, aimbots, wallhacks, god mode, patchers, or anything that disables anti-cheat, version checks, or related systems. Ordinary improvements are welcome. Cheat tools are not.

The notice is kept word for word at the top and bottom of `src/index.template.html` (and so of the built `public/index.html`). The anti-cheat, the modified-file check, the bank code and the save/friends protections are kept unchanged.

## Project structure

```
public/                    static site served by Vercel (output directory)
  index.html               generated by `npm run build` (not committed)
  css/styles.css           page styles (was the <style> blocks in <head>)
  css/loading.css          loading-screen styles
  assets/loading/*.jpg     loading-screen artwork, one file per map (generated from src/binary/)
  assets/data/asg-NN.*.js  embedded game data (textures, sounds, music, meshes), moved out of the HTML unchanged
  assets/manifest.json     list of every data entry and its type
src/
  index.template.html      page markup, with a marker where the game script goes
  game/game-01.js ...      the game script, in order (01 engine and maps, 02 gameplay and UI, 03 later systems including the anti-cheat)
  game/manifest.json       part order and checksums of the release build
  binary/loading-art.json  loading-screen JPEGs stored as base64 text, decoded into public/ by the build
tools/
  assemble.mjs             joins src/ into public/index.html and decodes src/binary/ into public/
  build.py, ast_edits.js, split.py   one-time pipeline that produced this layout from the original file
```

### Why the game script is still one inline script
The game checks its own integrity in the browser: it hashes the page's main inline script to spot modified copies in multiplayer, and it treats extra inline scripts as injected cheat code. Splitting the game logic into separate `<script src>` files would blind those checks, so the source is kept as ordered parts in `src/game/` and joined back into one inline script at build time. Only data (images, audio, meshes) was moved out of the page.

## Run locally
Requires Node 18+.

```
npm start            # builds public/index.html, then serves public/ with `npx serve`
```

Or build once and use any static server:

```
npm run build
python3 -m http.server 8080 --directory public
```

Open the printed address in a desktop browser. The first load downloads about 250 MB of game data.

## Deploy (Vercel)
The Vercel project is linked to this repository. `vercel.json` sets the build command (`node tools/assemble.mjs`) and the output directory (`public`). No other build step or dependencies are needed. Pushes to `main` deploy to production.

## Multiplayer
Multiplayer is peer-to-peer (WebRTC through PeerJS 1.5.4, using the public PeerJS signalling server and public STUN servers). It does not depend on the site's domain.
